- Stack: TanStack Start (React + Node server functions) with SQL Server via `mssql`. Server-only code lives in `src/server/*.server.ts` and is loaded with `await import(...)` inside server functions (the build fails if browser code imports `src/server/`); schema changes go in `database/schema.sql` and must stay idempotent (`IF OBJECT_ID(...) IS NULL`).
- Pages use `useStore()` (src/lib/store.tsx). `update(fn)` diffs the data before/after and sends only changed rows to `saveChanges` (src/lib/qrs.functions.ts, Admin only, one transaction), then reloads; access logs are written by `logAccess`.
- Roles are `dbo.users.role` (`Admin` | `User`); Users are view only. Passwords are hashed server-side and never sent to the browser (blank password on edit keeps the current one). The first account is created on the sign-in page.
- Keep quotation preparation staff in a dedicated master list and store the staff name as text on each quotation; why: preparation staff do not need login accounts and historical names must survive renames.
- Centralize client matching, manual number normalization and daily access counting in browser-safe quotation rules (`src/lib/quotation-rules.ts`); why: forms and future email triggers must use the same tested rules.
- Uploaded files live in `dbo.files` (`src/server/files.server.ts`); attachments keep the file's path and `/api/files/<path>` serves it to signed-in users only.
